# Worktree hygiene preservation and publication

The canonical `diskm` worktree-hygiene lane remains dry-run by default. Its existing recency, ownership, live-process, lock, index, operation, byte-preservation and ignored-data checks remain in force. Use isolated fixtures to validate changes; this repair does not authorize a live cleanup or deployment.

`--preserve-wip` commits eligible work onto a local WIP branch. Without `--push-wip`, or with `--no-push` / `--skip-push`, the worktree stays in place. With `--push-wip`, publication requires a bounded successful Gitleaks scan of reachable history, normal repository push hooks, and an exact remote-ref SHA match. Missing scanner/timeout support, a scan failure, authentication failure, hook failure or unverifiable publication keeps the worktree and local WIP copy. Only a genuine non-fast-forward or fetch-first rejection permits a normal push to `backup/<branch>-<date>`; no force push is used. Successful remote verification precedes non-forced WIP worktree removal. The manifest records local and remote-verified events, including the actual remote ref.

Credential-shaped names in ignored rebuildable dependencies do not themselves block preservation. Real root secrets and non-rebuildable ignored data still block. Ignored `evidence/` content is retained and listed as `DECISION-REQUIRED`: review the recorded path and choose a retention/preservation policy explicitly. The lane does not force-add or publish ignored evidence.

Completed and interrupted runs write `worktree_hygiene_summary.json` atomically in the existing state directory. The summary contains exact outcome counters, verified publication count, completed candidates, discovered/scanned/skipped repositories, and an unfinished repository/candidate. INT and TERM produce an interrupted, partial receipt and nonzero exit status. Re-run the same command to revisit unfinished repositories with all safety gates rechecked. SIGKILL and host loss cannot execute an exit trap; Git branches and earlier manifest entries remain durable, but the final summary is not guaranteed in those cases.

## Snapshot and history quality

Snapshot canonical status comes from finite, bounded effective coverage of at least 70 percent, not a warning-string equality test. Fresh, carried and frontier coverage retain their distinct meanings. The consecutive-coverage alert uses fresh `snapshot_coverage_pct` below 70 for six distinct capture timestamps, even when carried values raise effective coverage. Old effective-metric streak state is reset with a diagnostic rather than reused as fresh evidence.

Fresh partial-ledger availability remains useful and labeled `PARTIAL`; it no longer hides failed canonical publication health. The alert reports stale canonical publication independently. `history diff --days N` filters by actual capture date and displays observed span, sample count and capture dates. A recent Git commit containing an ancient capture is not a new observation. A sparse series remains partial; these code changes neither backfill captures nor establish 30 days of daily canonical publication.

## Uncovered roots

Registry entries prefixed `decision:` are report-only routes, not automatic sweeper coverage or deletion permission. They cover the supplied proposal groups without claiming a cleanup owner for mixed agent state, conversation backups, task evidence, system Developer data, or unowned log directories. Simulator Devices retain the existing explicit all-simulator and approval requirements. Browser proposals remain cache-only; profiles and account state are preserved. The supplied nine groups do not reconcile the original measured 17-root count. Actual reclamation, scheduling, sustained coverage and a complete 30-day daily ledger series remain unverified runtime outcomes.
