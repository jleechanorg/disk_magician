# Native volume history and expired Scratch completion

Base: `d4f555b028a78ecae16cd4b4b7640f82ffdc73a9`. Scope: one native Rust PR. No cleanup, installed service changes, or host rollouts. The operator's separate cleanup lane retains live ownership.

## Why
- At 23:41 PST on Nov 25 the installed native build was `dc640ae661b03018a1188a9e08037ca11826984f`. Mac `df -Pk` reported System used 13,339,596 KiB and Data used 726,445,512 KiB, with 32,716,904 KiB available shared by both. The scheduled snapshot currently asks for System by passing `/`.
- Native `state-commit` already publishes the capacity snapshot path; `history` only reads the legacy top-down ledger path. No current producer writes qualifying top-down v2 data. The retired frontier and observer plists are not an install remedy. `cleanup-worktrees` is not a native command; worktree layout/leases/slim/archive remain distinct. Do not recreate legacy removal.
- Linux systemd sent TERM on three 600-second service timeouts, with no new deletion receipt. The internal budget equals the supervisor timeout and the scan checks the clock on directory entry, not each entry of a flat directory. This explains lack of shutdown margin. A separate live manual Linux run recorded repeated global lsof enumerations, about 8.6 GB of process I/O characters and 9.4 million system calls in about two minutes while the parent consumed about three seconds of CPU. This establishes a hot path for that run, not phase timing of the three historical timeouts. `--path` on non-expired sweep admits files, not whole directories; `--expired --path` is presently rejected.

## Contract
1. Scheduled Mac capacity samples use the Data mount; stdin/stdout contract and explicit path choices stay unchanged. Linux retains root. New snapshots carry host, filesystem source and mountpoint provenance plus exact capacity used in KiB; their inventory status stays partial. An explicit Data sample may not silently fall back to System if the Data mount is absent. Do not label shared APFS container free space as dedicated Data free space.
2. `history --capacity --state-dir DIR --days 7|30` reads the existing Git snapshot path via the same bounded reader as top-down, with a separate 256-commit capacity cap (the normal four-hour cadence yields about 180 captures in 30 days; retain the existing inventory cap and both byte limits). It rejects old unscoped, malformed and out-of-window captures; accepts capacity only, deduplicates date coverage only (an intraday minimum still counts), and compares only the newest qualified host/source/mount tuple. Report the actual dates, span, and lowest observed used bytes, not day-completeness or a whole-disk inventory. Matching filesystem names do not establish strong hardware identity after replacement; receipt scope is one per-host state repo. Default `history` remains strict classified/inventory mode. Missing full authority stays missing; no fabricated free-space attribution or bucket growth.
3. Expired sweep accepts an explicit exact candidate path with its existing preview default and explicit clean mode. Select only paths admitted by the current whole-root candidate enumerator; no nested stale child, symlink alias, cross-device candidate, or cap override. Avoid unrelated expensive age/protection work when the selected units contain no Git stores; Git still requires a complete borrower census before qualification and the existing fresh census before deletion. Preserve leases, open paths, evidence, stage recovery, durable removal receipts and whole-unit policy. Exact mode never replays prior intents; even an interrupted exact selection is recovered by the existing whole-root sweep. If a Git store appears before staged verification, reclassify it and require a fresh complete borrower census or hold; never treat a skipped census as complete. Do not resume stale removal verdicts via a cursor.
4. Keep the existing internal window and reserve supervisor headroom for reporting/recovery. Check remaining time during flat directory traversal and before starting further removals. Skip the global open-file listing for already-held or incomplete candidates; before stage, take a fresh listing for the original path, and after stage take another fresh listing for both original and staged prefixes together. Preserve existing error/warning/partial-output rejection for either prefix and do not cache a negative result across candidates or between stages. Completed stages remain durable; pending work is explicitly partial, not successful. Blocking kernel I/O and deletion inside an already authorized stage cannot promise a hard internal deadline; systemd remains the outer bound. Actual host completion must be measured separately from fixture evidence.

## Assumptions and recommended defaults
- Re-enable legacy collectors vs implement a new full frontier vs split native capacity from legacy inventory. Choose the split: native capacity gives trustworthy observed-window floors using the installed publisher; full allocated-byte classification needs distinct APFS clone accounting, coverage bounds and reviewed producer design. No sound classified floor can be restored from capacity alone.
- Raise timeout alone vs remove safety probes vs reserve reporting slack and enable bounded exact selection. Choose the last: timeout headroom alone does not make a large volume finish; exact mode retains the Git census whenever needed. A missing/expired scan is never permission. Prefer one listing for two simultaneous targets over lsof +D, per-UID filtering, or cached process output: those alternatives do not preserve the existing observation scope.
- Existing native compiled Rust code is canonical. No second dispatcher, generated legacy source, test-only flags in production, provider calls, or wider deletion authority. Under the 14,100 Rust physical LOC and +250 legacy ceilings. A real seven-day observation window starts after an authorized rollout; retrospective legacy data stays untouched.
