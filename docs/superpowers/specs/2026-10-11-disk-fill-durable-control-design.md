## 2. Goals

1. Close the loop at creation. Every governed producer calls `diskm admit` before writing; admission decides on projected free (fresh `df` free minus the request, less a concurrency margin), plus per-class byte budgets where a class can be measured reliably. v1 admission is **best-effort**: it holds no reservation, so it has no finite bound on bytes written by producers it already admitted (§7.1).
2. Bound what admission cannot see. Producers outside admission are detected by the birth audit; admitted births are counted from the admission event log. BLACK/FLOOR refusal stops new governed writes; it is a best-effort backstop, not a guaranteed floor (§7.6).
3. Shorten retention where it is provably safe and already sanctioned: owner-exit release (D1) and the existing 3-day `cleanup_worktrees.sh` rule, each behind one final per-artifact check that requires positive provenance.
4. Make the controller observe itself. A dead actuator, blind admission, a stale tick, a starved actuator, material bypass or a rising trough is the first line of `diskm status`.
5. Measure success by df: the 7-day minimum free, samples under 15 GiB free, and the daily used trough.

## 3. Non-goals

- Replacing existing actuators or schedules. `main_sweeper` (including `snapshot_commit.sh`, every tier and the health phase) and `pressure-sweep` **stay installed and unchanged**. Revisit after 14 days of governor receipts.
- A reservation ledger in v1 (deferred, §12).
- Moving `/advice` reviewer copies to linked worktrees (dropped, §6).
- Full attribution (bead `4y6`); reducing `~/.codex/sessions*` or `~/.claude/projects` (never-delete); Linux portability beyond what scripts already support.

## 4. Anti-goals (must not happen)

- Another sweeper tier, or a "GiB reclaimed" report without `df_delta_bytes`.
- Approval gates no scheduled job can satisfy; expiring standing decisions.
- A deletion justified by age or location alone, a new deletion rule not named in a recorded decision and in `CLAUDE.md`, or any removal that skips `artifact_removal_verdict` (sole exclusion: the guarded `/advice` own-copy teardown, §11).
- Admission that goes blind because du is slow, or a claim that v1 admission prevents concurrent oversubscription (it does not; §7.1).
- Claiming the loop is closed while bypass births exceed the §7.5 SLO.
- Treating lease TTL expiry, quiet time or a session-end event as proof that an owner is dead.
- Loosening `~/.claude/hooks/protect-worktrees.sh`, or giving agents removal authority.
- Recency proxies, ad-hoc cleanup scripts, never-delete paths, keyword/heuristic classification (classes come from a fixed governed-root table; the hook does literal syntax matching).
- Auto-pausing CI runners without D4.

## 5. Constraints

- **One entry point.** New `diskm` subcommands in `src/disk_magician/disk_magician.sh` and `disk_magician.sh`, synced by `scripts/sync_package_tree.sh`.
- **One removal gate.** Every removal first calls `artifact_removal_verdict` (C14) immediately before the destructive call and obeys it on every path, existing sweepers included (sole exclusion: `/advice` deleting its own copy behind C14's content checks, §11). Worktrees are then removed by `wrh_remove_now` (byte-verified, #120) in quarantine mode; non-git roots by `quarantine_remove` (two-phase, C14).
- **Recency** only through `scripts/lib/worktree_recency.sh`, fail closed. **Owner liveness** only through `lease_owner_state` (pid + `start_epoch`); `unknown`/`unreadable` = alive = keep.
- **Locks.** `govern.lock` (one tick at a time; an overlapping tick exits `skipped_tick_lock`). `state.lock`, one `fcntl.flock` (Python; macOS has no `flock(1)`) taken by **every** writer of `budget.json` and `admission/events.jsonl`: each `diskm admit` decision, the tick's and the daily job's read-merge-replace, and event-log rotation. Each holder rereads current state inside the lock and never holds it across du, `git fetch` or an actuator. Actuators keep their own locks; a held lock yields `skipped_lock`, never a wait.
- **Timeouts** via Python `subprocess` timeouts (no `timeout(1)` on macOS).
- **Deploy.** Version bump, `tools/deploy_uv_tool.sh` from clean origin/main, verify `deployed.json` plus a scheduled receipt.
- **PR size.** At most 150 production lines per PR, or the size-tiered gate.
- **Disk-full operation.** The tick and admission work at about 5 GiB free: state writes are atomic and under 64 KiB, a failed write keeps the previous file, an event-log append failure is recorded as `admission_degraded:log` and never changes the decision. Admission never runs du.

## 6. Approaches considered

1. **Budget governor (winner):** free-space zone + per-class budgets, `diskm admit` on projected free, 10-minute `govern` tick, df-verified receipts. Closes the loop; does not on its own shorten retention.
2. **Lifecycle-first:** leases on every kind, detached worktrees, session-exit release. Smaller footprint, but no setpoint.
3. **Policy and decisions:** decision record, parked set, trough alerts, 90-day expiry. Expiry rebuilds the babysitting.

**Chosen:** design 1, with grafts: leases on every kind (C3), session-exit release (C8), detached scratch for producers that need no isolation (C4, narrowed); the decision record (C11), the parked set and trough alerts. The 90-day expiry is dropped.

**Dropped after review:** converting `/advice` (`run_primary_pair.py`) to linked worktrees. It deliberately uses `git clone --no-local` with `origin` removed so full-permission reviewers cannot touch the user's refs, config, hooks or stash, and `shutil.rmtree`s each clone at the end behind `advice_own_copy_ok` (§11). Advice is governed by admission instead (C2, C7). **Dropped in r6:** the reservation ledger (§12).

## 7. Chosen design

### 7.1 Control model

```
projected   = df_free - est                                  # fresh df on every admit call
admit zone  = zone(projected - margin)                       # margin = concurrency_margin_gb, pilot default 10
tick zone   = zone(df_free)
zone(x)     = GREEN (>=100) | ORANGE (60..100) | RED (30..60) | BLACK (15..30) | FLOOR (<15)
class overage = class used_gb - budget_gb                    # only for classes with a fresh measurement
```

**Admission (C2).** `diskm admit --class C --est-gb N [--producer K] [--dest P] [--source S]` takes `state.lock`, reads `df` (5 s timeout), decides by the plan's policy table, appends one line to `admission/events.jsonl` (`admit_id, at, class, producer, source, est_bytes, dest, ci_job, tool_use_id, decision, df_free_bytes`), prints the `admit_id`, and releases the lock. After its command succeeds the producer runs `diskm admit --confirm <admit_id>`, which logs an `admit_confirm` event with the dest's dev + inode (the hook confirms from PostToolUse by `tool_use_id`, for a single simple command only, C6); a failed command confirms nothing. The lock orders decisions and the log; it does **not** account for admitted bytes that have not landed yet. **Honest limit: v1 admission is best-effort.** Callers admitted close together each see about the same `df`, and an admitted writer (a CI job, a long clone) keeps writing after its admission, so v1 has **no finite bound** on bytes from writers already admitted; an under-estimate adds to it. Three things limit, not bound, it: the margin; the **hard floor** (`projected < 15 GiB` → 75 for every governed class in every stage once D2 is recorded), which stops only *new* governed writes; and the BLACK response below. The pilot reports `admit_burst_bytes` = max Σ `est_bytes` admitted (0/10) in any 600 s window as a diagnostic only. Progress is gated on what df shows: D3 requires zero observer samples under 15 GiB free in a valid pilot (§7.4), whatever the margin was. The margin is a pilot epoch parameter: a change (`diskm budget set-margin`, recorded) starts a new pilot, and two consecutive valid epochs that breach the floor trigger §12 without waiting for D3.

**Exit-code channel.** `diskm admit` never runs a command: its rc is the decision alone (0 admit, 10 warn and proceed, 75 refuse, 76 queue with `retry_after_s`). A caller runs its command only after admit returns. A caller exits with its reserved code 75 only when admission refused and the command never started, and prints `disk-admission: refused class=<C> rc=<75|76>` on stderr first; every other caller exit is the command's own. A 76 retry happens once, only before the command has started.

**Emergency rows are stage-independent once D2 is recorded.** Admission zone FLOOR → 75, BLACK → 76 (`retry_after_s=600`) in every stage. Callers retry once after `retry_after_s`, then stop. A tick whose df zone is BLACK or FLOOR runs zone-trigger actuators first and, **only when C14 is deployed on every pressure-sweep delete path** (`artifact_removal_verdict --self-test` passes from the deployed tree), kickstarts the existing pressure-sweep job (`launchctl kickstart gui/$UID/com.jleechanorg.disk-magician-pressure-sweep`; its own lock prevents overlap). Before that the tick records `kickstart_blocked:c14_missing` and pressure-sweep keeps its own unchanged schedule; the governor adds no destructive triggering before C14. BLACK/FLOOR refuses **new** governed writes only.

**Each 10-minute `diskm govern` tick**, under `govern.lock`, has **one absolute monotonic deadline** `D = start + 540 s`; every phase's budget is derived from `D − now`. In order: (1) reads df and writes the tick zone to `budget.json` (under `state.lock`) before anything else, handling BLACK/FLOOR as above (`floor_breach`, kickstart); (2) quarantine reconciliation (C14) with budget `min(120 s, D − now − 300 s)` (60 s in BLACK/FLOOR, which also skip steps 3 and 5, so zone actuators start within about 90 s of the tick) and a resumable cursor: unfinished sidecars stay quarantined for the next tick, and a timeout never authorizes deletion; (3) measures **one** du class (round-robin, about hourly each, 60 s timeout, outside `state.lock`; on timeout the prior value stays and `stale_s` grows; skipped as `skipped_measure_lock` while the daily job holds `measure.lock`); (4) reads Colima from the observer's `colima.root_allocated_kb`; (5) runs the birth audit (C7, at most 120 s of du per tick); (6) runs act-mode actuators through the scheduler (C10) in the time left; (7) writes one receipt per actuator with `free_bytes_before`, `free_bytes_after` and `df_delta_bytes`.

**Daily measurement is its own job.** `diskm govern --daily-measure` (launchd, 03:00 local, `measure.lock`, 900 s) measures every du class (60 s) and every `df_delta_only` class (120 s, accounting only), carrying prior values forward on timeout and marking them `carried`. It merges into `budget.json` by rereading the file inside `state.lock`, so neither it nor the tick can overwrite the other's fields.

**Admission never goes blind on du; df failure is a recorded degraded mode.** `diskm admit` reads only class overage from `budget.json`; a class measurement older than 3 h drops that class's overage term. If `df` fails, admit decides on the last tick's `free_bytes` when ≤ 15 min old (`admission_degraded:stale_df`); otherwise it returns 10, never 0, and logs `admission_degraded:blind` with an alert, unless the last zone within 60 min was BLACK/FLOOR, in which case it refuses per the emergency rows. A caller that cannot run `diskm admit` or gets any other rc proceeds, logs `admission_degraded:caller` and prints one warning line. Degraded admissions count as bypass (§7.5).

**APFS copy-on-write.** A class whose du is unreliable is `measure: df_delta_only`: no overage term, `trigger: zone`, effect judged by receipt `df_delta_bytes`. Pilot default: `codex_documents`, `tmpdir_scratch`; the pilot moves any class whose du-reported reduction disagrees with the df delta by more than 50% on 3 or more runs.

**C14 rules.**

- **Git content.** Local remote-tracking refs are never trusted (a narrowed fetch refspec leaves stale ones). The remote set is the live advertisement: one bounded `git ls-remote <url>` per remote URL (`GIT_TERMINAL_PROMPT=0`, `GIT_ASKPASS=/usr/bin/false`, 30 s timeout) run inside the removal-time verdict, never cached or carried over from nomination, so a branch deleted or force-pushed since nomination keeps; failure or timeout → `kept:remote-unverified`. A remote change between this call and the rename is a residual race. The commits the removal would destroy must be empty in `git rev-list <tips> --not <advertised SHAs present locally>`, else `kept:not-pushed`. **Scope follows what is destroyed.** An independent repository (clone, nested repo, `/advice` copy) loses everything: `<tips>` = `--all --reflog` (`--reflog` catches a commit kept only by a reflog after a reset or rebase; `--all` covers tags and `refs/stash`). It must also hold no unreachable object of any type: `git fsck --connectivity-only --unreachable --no-reflogs --no-progress` (inside C14's deadline, else `deferred`) printing any `unreachable` line, commit, tree or blob → `kept:unreachable-object` (a `git stash create` object, a dropped stash, a staged-then-reset blob holding unique bytes). Re-staged edits leave such objects, so more clones are kept; those bytes are reported per class like every other kept reason. An object-mtime rule misses packed objects. Its `.git` outside `objects/`, `refs/`, `logs/`, `packed-refs`, `index` and `*HEAD` (hooks, config, info, any added file) must also equal the baseline manifest its producer recorded at creation (lease or `/advice` receipt `git_meta`): a difference → `kept:git-metadata`, no baseline → `kept:git-unbaselined`. A linked worktree loses only its own state: `<tips>` = its branch, the branch reflog, and every object id under its admin dir `<common-dir>/worktrees/<id>/` (`HEAD` and every other `*HEAD` file, every file under `refs/` and `logs/`), enumerated from the directory rather than a name list, so `refs/rewritten/*`, `refs/bisect/*`, `refs/worktree/*` and the HEAD reflog are covered; an unreadable entry or a non-`files` ref backend → `kept:check-failed`, and a rebase, merge, cherry-pick or bisect in progress → `kept:dirty`. The admin dir is part of the removal scope: it may hold only git-generated names (`HEAD`, `ORIG_HEAD`, `FETCH_HEAD`, `AUTO_MERGE`, `index`, `commondir`, `gitdir`, `logs/`, `refs/`, `locked` carrying C14's own `dm-quarantine:<id>` reason, and `config.worktree` only if absent, empty or byte-equal to the baseline recorded at `git worktree add`); any other entry or a non-default `config.worktree` → `kept:admin-unknown`. Its entries join the verified inventory, so a change after the verdict keeps them. Other worktrees' commits and shared refs survive the removal and do not veto it; so do unreachable objects, which live in the common object store that worktree removal never deletes, so the `fsck` rule does not apply. **Every** repository found (linked worktree, ordinary clone, nested repo, `/advice` copy) must show no staged or unstaged change to a tracked file or submodule (`git status --porcelain=v1 --untracked-files=all --ignore-submodules=none` has no line other than `??`/`!!`) and no index entry flagged assume-unchanged or skip-worktree (`git ls-files -v`), else `kept:dirty`; its untracked and ignored files go to the provenance rule below. A registered linked worktree also passes `wrh_removal_verdict` (clean incl. untracked, hidden state, ignored secrets, non-rebuildable ignored data, live cwd, AO, HEAD pushed by live `ls-remote`). **Repository discovery** walks the whole candidate, the candidate itself included, with no `-prune`, so a repository nested inside another repository's tree is found: a `.git` directory or file, or a bare repository (a directory holding `HEAD`, `objects/` and `refs/`), at any depth. Every repository found gets every git check above as an independent repository (a bare one has no working tree, so only the status check is vacuous). A walk that is incomplete (unreadable directory, error) → `kept:check-failed`; one that runs out of time → `deferred`; neither removes. A bare `/tmp/pr-123/backup.git` holding an unpushed commit is therefore `kept:not-pushed`.
- **All non-git content needs positive provenance**: every file outside git tracking (untracked, ignored, or in a non-git root) must be (a) listed, with matching sha256 and size, in the **upload manifest** of a published-evidence receipt (C3), **and** its own object re-verified at removal: one bounded metadata read per object (cached per run, inside C14's deadline) shows the recorded generation and a hash equal to the manifest's. An object deleted, overwritten (new generation), expired (evidence objects have 30-day retention) or unreadable → unproven. The manifest match proves the file is unchanged; the removal-time object check proves a copy still exists. A file added or changed after publication, a receipt without a manifest, or one without `verified_at` is unproven, and a lease or producer manifest without a verified publication proves nothing; or (b) **rebuildable**: an ignored path matching the shared rebuildable-ignored allowlist (`scripts/lib/worktree_ignored.sh`, #153: caches, venvs, `node_modules`, build output), inside a repository that passed the git checks, with no secret-like file under it (the `wrh_removal_verdict` patterns); or (`--kind rebuildable`) a path under the fixed **cache-root table**, the cache classes today's sweepers target: `~/.cache/uv`, `~/.cache/pre-commit`, `~/.npm/_cacache`, the opencode cache subdirs and bazel output bases of `cleanup_dev_caches.sh`, Xcode `DerivedData`, CoreSimulator `Caches` and `Temp`, and the `venv`/`.venv`/`venv.bak` dirs `cleanup_worktree_venvs.sh` strips. A root is in the table because its tool regenerates it; or (c) (`--kind ephemeral`) **declared-ephemeral**: a candidate matching a row of the declared-ephemeral table below whose newest content is older than that row's retention. Anything else is `kept:unproven-content` and goes to `parked`, whatever its age, location or name. Outside that table there is no age-only or location-only rule.

- **Quarantine: two-phase, crash-safe, bound to the verdict.** Non-worktree roots go through `quarantine_remove`. C14's `remove` verdict, taken immediately before, also outputs the **verified inventory**: each entry's relative path, type, dev + inode, size, the sha256 its checks computed for each regular file, and each symlink's target. Only that inventory may be deleted; nothing is re-hashed into it later. The sidecar `<root-parent>/.dm-quarantine/<id>.json` (original path, `lstat` device + inode, producer, lease/receipt id, inventory, `phase`) is fsynced before each phase change. It is the one state file that may exceed 64 KiB (it holds the inventory); a failed `intent` write (ENOSPC) aborts before the rename and the artifact stays in place, kept. **Phase 1, commit point:** `intent` is written, then the artifact is renamed with `renamex_np(RENAME_EXCL)` into `.dm-quarantine/<id>` (directory mode 0700, random id; atomic; only when `realpath` and `stat -f %d` show the same device, else `kept:cross-device`, never copy). The moved object's device + inode must equal the record (a path swapped before the rename fails here); the open-file and cwd tests rerun; every entry is re-hashed through directory descriptors and compared with the inventory. A live user or any changed, missing or extra entry rolls back with `renamex_np(RENAME_EXCL)` and keeps; a recreated original path or a missing exclusive call leaves it quarantined with `quarantine_conflict` / `exclusive_rename_unavailable` (never check-then-rename). **Phase 2, delete from quarantine only:** `phase: deleting`; there is no rollback. Deletion, first run or resumed, walks only `.dm-quarantine/<id>` through directory descriptors (`O_DIRECTORY | O_NOFOLLOW` on every descent; a symlink or replaced directory is never followed) and `unlinkat`s an entry only if its type, dev + inode and sha256, re-read through the descriptor just before the unlink, match the inventory; a changed or uninventoried entry is kept. **Stated concurrency limit:** a write between C14's hash and the rename is caught by the phase-1 re-hash; after the rename only a process holding an earlier descriptor (refused by the open-file test) or one that discovers the 0700 path can write, and a write between an entry's last hash and its unlink is not excluded. The sidecar is removed last. **Linked worktrees** are first locked (`git worktree lock --reason dm-quarantine:<id>`; prune skips locked worktrees, so the admin dir with its private refs and reflogs survives), renamed the same way, then `git worktree repair <quarantine path>` so the registration names the new path; rollback renames back and repairs again; phase 2 deletes the checkout, then tears down exactly this worktree's registration: its admin dir `<common-dir>/worktrees/<id>/`, whose `gitdir` must still name the quarantine path and whose entries must match the inventory, is deleted entry by entry through descriptors. A repo-wide `git worktree prune` is never run, so sibling admin dirs are untouched. Teardown is complete when that admin dir is gone and `git worktree list --porcelain` no longer names the path; only then is the sidecar dropped. Reconciliation reruns `repair` for any worktree named in a sidecar. **Reconciliation per crash point:** (1) `intent`, original present, nothing in quarantine → drop the sidecar; (2) `intent`, object in quarantine with matching identity → roll back, and the next run decides afresh with a new verdict; (3) `deleting`, partly deleted → continue with the same per-entry check; a changed or uninventoried entry is kept and the remainder stays quarantined with `quarantine_partial_kept`; (4) object gone → drop the sidecar (worktrees: first finish the targeted admin-dir teardown above). Identity mismatch or a missing or malformed sidecar → keep and alert. Rollback never claims to restore deleted files: phase 2 deletes only inventory entries C14 proved disposable, so an interrupted delete loses only those. Kept quarantined artifacts are never auto-deleted, count in `parked` bytes, and stay recoverable with `diskm quarantine restore <id>` (identity-checked, `RENAME_EXCL`). Linked worktrees are claimed with `lease_write_pending` and rechecked just before `wrh_remove_now`.

### 7.4 Budget model and pilot week

Usable `U = 895` GiB; pilot class budgets `S = 108` (35 + 15 + 10 + 3 + 15 + 30); minimum-free target `F = 30`.

- **Sizing aid, not a gate.** Budgets are sized with `B_est + S + W_est ≤ U − F`, where `B_est = df used − Σ class used` is base space outside governed classes and `W_est` = 1.25 × the largest daily swing of `B_est` over the pilot. Both are **estimates**: on APFS, du of clone-heavy classes double-counts shared blocks (the `code_sign_clone` case, §1.4), so `B_est` can be understated. They are reported, labelled `estimate`, and excluded from every pass/fail. A daily-measure snapshot with any `carried` value reports `B_est` as `incomplete`.
- **Pass/fail is df-only:** the §7.6 indicator, the §7.5 births SLO and the §9 metrics.

**Pilot start condition.** C14 is deployed and enforcing on every §7.2 delete path; admission (C2) with its event log, `wtn_admit`, the hook (C6), `/advice`, evidence-producer and CI admission (C13), and the birth audit (C7) are deployed, each with a scheduled receipt or an event-log line; D2 is recorded; and a live emergency probe passed: `diskm admit --probe` with `--est-gb` chosen so `projected − margin` = 20 GiB returned 76 (if free is already below that, `--est-gb 1` must return the current zone's row: 76 in BLACK, 75 in FLOOR).

**Pilot week.** Govern runs in observe mode (emergency rows active) for 7 × 24 h from `pilot_start`.

- **Qualifying day:** observer samples ≥ 95% of expected, govern receipts ≥ 95% of expected ticks, every du class fresh (≤ 3 h) in ≥ 80% of ticks. At least 6 of 7 days must qualify.
- **Invalidation (rerun from a new `pilot_start`):** fewer than 6 qualifying days; a deploy that changes admission, audit, hook or measurement code (`deployed.json` hashes); a stage, D2, margin, budget or `estimates.json` change (the effective estimates are frozen at `pilot_start`; calibration accumulates in `estimates.pending.json` and applies only through `promote-estimates`, which starts a new epoch); the launchd fleet unhealthy for more than 2 h in total.
- **Reported, not invalidating:** `admit_burst_bytes` per day against the margin; `B_est`, `W_est`; unknown-size births by count; the §7.6 exposure split before and after any reclaim change that lands mid-pilot.

D3 records budgets and margin from the pilot. Enforcement may not pass `warn` before D3, and D3 needs a valid pilot with the §7.5 births SLO met and **`pilot_floor_ok`**: zero observer samples under 15 GiB free in the pilot week (observed overshoot against the floor; whether the margin was right is not an input). If it fails, the remedy is a new prevention point or a larger margin, either of which starts a new pilot epoch; two failed valid epochs in a row trigger §12. Each stage change has a tested rollback that keeps the emergency rows (`diskm budget set-stage`).

### 7.5 Coverage: prevention first, detection second

| Producer | Prevention point | Lands before pilot |
|---|---|---|
| `diskm worktree-new` | `wtn_admit` → `diskm admit` | yes |
| `diskm scratch-new` | admit before create | yes |
| Agent shell `git worktree add` / `git clone` / `cp -R` | PreToolUse hook (C6) | yes |
| `/advice` clones in `$TMPDIR` | `run_primary_pair.py` calls `diskm admit --class tmpdir_scratch --producer advice` once per run before its clone step | yes |
| Evidence bundles under `/private/tmp/<repo>/evidence` | evidence entry points use `scratch-new --kind evidence` | yes |
| CI jobs | ezgha job-started hook (C13) | yes |
| Anything else (subshells, `eval`, scripts, apps) | none: birth audit detects persistent entries | n/a |

**SLO metric.** Births per C7: filesystem-observed destination generations only. CI jobs are reported separately in `ci_admission` (C13) and enter this ratio only as an audited filesystem birth at their workspace, so admitted CI jobs cannot dilute filesystem bypass. Admitted = a birth whose generation has an `admit_confirm` from a non-degraded 0/10 attempt (C7; compound hook commands never confirm, C6); bypass = every other audit birth, including one whose only attempt was `admission_degraded:*`. **Bypass births ratio** = bypass births / all births, < 10% per pilot day and per week after; this is the certified SLO. `attempt_unconfirmed` events are reported and never enter the ratio, so failed commands and repeated attempts cannot dilute bypass. **Bypass bytes ratio** = bypass bytes / (bypass + admitted `est_bytes`) with `bytes_unknown` charged per C7; it is reported as an **estimate** and, when unknown-size births exceed 5% of births by count, as `estimate_unbounded`. **Coverage limit, stated:** an ungoverned producer that creates and deletes a tree between two ticks is neither admitted nor audited; it appears only in the df trace (§7.6, §9). The SLO therefore certifies births that persist ≥ one tick, not all disk writes. D3 cannot be recorded, and the loop is not called closed, while the births SLO fails; the top bypass roots become the next prevention points.

### 7.6 Floor breach: backstop, indicator and runbook

Admission stops new governed writes; it cannot stop an admitted writer mid-copy, a concurrent admitted burst landing after the same df reading, a bypassing producer, or a running CI job. The pilot reports an **empirical exposure indicator** (not a bound, not a certification):

```
r_peak      [B/s] = max over sliding 600 s windows of Δ(df used) / 600      # no subtraction of admitted or reserved bytes
T_detect    [s]   = 600 (tick) + observer sample interval
T_reclaim   [s]   = max observed zone-tick start → first receipt with df_delta_bytes > 0
exposure    [B]   = r_peak × (T_detect + T_reclaim) + admit_burst_bytes
floor_margin_ok   = exposure ≤ 15 GiB;  no positive reclaim receipt observed → margin_unknown (fails)
```

Bursts shorter than 600 s are averaged into their window, so `r_peak` can understate a short burst; the pilot reports `sample_interval_s` and the largest single-sample Δ beside it. Worked example: a 12 GiB rise in 600 s gives 0.02 GiB/s; with `T_detect` 660 s, `T_reclaim` 240 s and a 10 GiB admitted burst, exposure = 0.02 × 900 + 10 = 28 GiB → false. `floor_margin_ok` is reported, never a gate: "zero samples under 15 GiB" (`pilot_floor_ok`, §7.4; §9) is the empirical acceptance test.

When free < 15 GiB, the tick: (1) writes `floor_breach` first with the top growing roots from the audit, event log and observer; (2) runs every zone actuator, escalation ladder first, and kickstarts pressure-sweep if C14 is active; (3) prints the CI pause command (`launchctl bootout gui/$UID/<ezgha label>`) and Colima producer state, pausing CI only with D4; (4) records `tmutil listlocalsnapshots /`. Manual runbook printed by `diskm status`: identify the producer; ask the user before pausing CI runners; `colima stop && colima start`, then `colima ssh -- sudo fstrim -av`; list parked worktrees; never hand-`rm`.

## 11. Risks

- **Admitted writers overshoot.** Accepted in v1 (§7.1): best-effort, no finite bound; limited by the margin, the 15 GiB hard floor and BLACK; `admit_burst_bytes` and `burst_over_margin` are diagnostics; two consecutive valid pilot epochs that breach the floor trigger §12.
- **A bypassing or admitted producer writes faster than reclaim.** Not prevented; the §7.6 indicator, `floor_breach` and `bypass_high` name the root, which becomes a prevention point.
- **Estimates are wrong.** Per-producer calibration from audited births (C2), promoted only between pilot epochs; `cp -R` sizes its source; df catches landed bytes on the next admit.
- **Stricter C14 keeps more.** Declared-ephemeral rows E1–E7 keep today's reclaim of `/private/tmp` output and PR scratch, aside sessions, antigravity brain dirs, llm-inspector captures and rotated supervisor logs, at today's retention. What C14 newly keeps is content a data-loss check catches: dirty or unpushed repos, secret-like or non-allowlisted ignored files, and live or open content. It also keeps independent clones in `/tmp` without a `.git` baseline (`kept:git-unbaselined`) until their producers record one (Task 7). That share of `cleanup_tmp.sh` clone reclaim stops until then. The table widens only with a `CLAUDE.md` amendment. Task 0 baselines and `c14_kept_bytes` show the newly kept bytes per class; `reclaim_starved`, `parked_large` and the trough alert show the cost. The fix is at the producer, never a looser verdict.
- **Base space is larger than assumed.** `B_est` is an estimate only; budgets are judged by df in the pilot and D3 lowers them first.
- **Reuse hands an idle agent's worktree to a new owner.** Pending-lease claim, owner `dead`/`released`, C14, conditional branch delete.
- **Crashed `/advice` clones have no remote.** Disposable when the runner's `receipt.json` records source repo, resolved SHA, runner pid + `start_epoch`, an overlay manifest (path + sha256 of every file in `.advice-review-documents/`) and the clone's `git_meta` baseline taken after the clone and origin removal (C14 git rule), which the `.git` metadata still matches (else `kept:git-metadata`, e.g. a reviewer-written `.git/hooks/` file); the runner is dead; ≥ 2 h idle; `rev-list --all --reflog --not <sha>` empty; no unreachable commit (C14 `fsck` rule); no tracked change (C14 git rule); the source still has the SHA (`git -C <source> cat-file -e <sha>^{commit}`, else `kept:source-missing`); and the overlay matches the manifest exactly (else `kept:overlay-unproven`). Missing receipt → `kept:check-failed`. **Normal teardown** is the runner deleting its own copy, not a C14 removal (C14 would keep it: the runner is its live owner). `advice_own_copy_ok` runs before the `rmtree` and requires: the receipt's pid + `start_epoch` are the running process; the source still has the SHA; `git rev-list --all --reflog --not <sha>` is empty and the C14 `fsck` rule finds no unreachable commit; and the same repository content checks as C14 (`c14_repo_content_ok`, shared code): no staged, unstaged or submodule change to a tracked file, no assume-unchanged or skip-worktree entry, no untracked file outside the receipt-listed overlay, the overlay matching its manifest, no ignored file outside the overlay unless it is on the #153 rebuildable allowlist with no secret-like file under it, and `.git` metadata equal to the receipt's `git_meta`. Any failure keeps the copy (`advice_teardown_kept:<reason>`), and the crashed-clone rule above then keeps it too. Reviewer verdicts are captured from reviewer stdout before teardown; anything a reviewer leaves in the working tree keeps the copy.
- **The disk is too full to write state.** Writes under 64 KiB, atomic replace keeps the previous file, event-log append failure never changes a decision; the plan's stress test runs a tick at about 5 GiB free.

## 12. Deferred (v2): reservation ledger

Not in v1. Built if two consecutive valid pilot epochs breach the 15 GiB floor (§7.4), or production shows a `floor_breach` attributable to concurrent admitted writers. Acceptance criteria, taken from rounds 3–4:

1. A reservation is bound to the writer's process group/session, created before the command runs; wrapper death does not release it.
2. Release is a request: a bound reservation stays charged until its writer group and session are empty, including CI job descendants; any force-release is a separate, unsafe admin command.
3. Writes are admitted only through the wrapper, or direct reservations carry independently recoverable writer identity; an enforced maximum reservation size exists.
4. Losing ledger and journal keeps admission closed until every outstanding charge is bounded from durable evidence; an apparently empty process scan is not proof.
5. The admission result travels on a channel separate from the command's exit status (started, reservation id, decision, command rc); retry only when the command never started.
6. Journal append, ledger replace and compaction run under the same lock as reserve/bind/release, with crash tests after fsync-before-replace and replace-before-return.
7. No metric subtracts reservation changes from df changes.
